# P1-P2 产品定位泛化与研究画像复盘

## 做了什么

- 将产品主定位从「医疗 AI 每日情报」调整为「AI+X 交叉研究雷达」。
- 批量更新 README、页面标题、邮件标题、摘要 prompt 和内容生成 prompt 中的核心文案。
- 在 `config.yaml` 新增 `domains` 配置，覆盖 `AI + Healthcare`、`AI + Biology`、`AI + Materials`、`AI + Education`、`AI + Finance`、`Robotics + Embodied AI`、`HCI + Agents` 等方向。
- 为 `user_research_profiles` 增加结构化画像字段：
  - `profile_json`
  - `negative_keywords`
  - `audience`
  - `preferred_sources`
- 新增 `expand_research_profile()`，把自然语言研究方向解析为核心方法、应用领域、邻近方法、实体、排除关键词和用户受众。
- 保留旧的 `expanded_keywords` 字段和调用方式，避免破坏现有订阅与推送逻辑。

## 为什么这么做

单一医疗 AI 适合作为冷启动样板，但无法覆盖计算机研究越来越交叉的现实。新的定位把系统从「垂直领域日报」升级为「研究方向驱动的跨领域雷达」：用户不必手写复杂检索式，只要描述课题，系统就能构造画像并据此召回、排序和解释推荐。

## 优点

- 产品天花板更高，可以自然扩展到 AI+生物、AI+材料、AI+教育、机器人、HCI、金融科技等方向。
- `domains` 让数据源和标签可配置，后续新增方向不需要改核心代码。
- 结构化研究画像比关键词更适合做推荐解释和跨领域迁移判断。
- 兼容旧字段，迁移风险较低。

## 代价和不足

- 文案已泛化，但部分历史功能仍带有内容创作和医疗样例痕迹，需要后续慢慢拆分。
- 结构化画像依赖 LLM，缺少 API key 时会退化为旧关键词逻辑。
- 当前 `domains` 只是配置层，还没有完全接入召回权重和 UI 筛选。

## 简历/项目介绍表达

> 将原垂直医疗 AI 情报工具泛化为 AI+X 跨领域研究雷达，设计可扩展领域配置与结构化研究画像，将用户自然语言研究方向解析为核心方法、应用场景、邻近方法和排除关键词，为个性化推荐和推荐解释提供基础。

## 复盘

这一阶段最关键的判断是：不要做「全学科搜索引擎」，而是做「研究方向驱动的每日推荐」。前者会和 Google Scholar、Semantic Scholar 正面竞争；后者可以用少而准、中文解释、跨领域启发形成差异化。
