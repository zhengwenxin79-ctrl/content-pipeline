# P8 MVP 前端研究雷达体验复盘

## 做了什么

- 将首页首屏从单纯的「今日情报列表」升级为「AI+X 交叉研究雷达」产品入口，明确传达：
  - 每天 5-10 篇高价值推荐
  - 研究方向驱动
  - 中文结构化阅读卡片
  - 推荐理由、迁移价值和反馈闭环
- 调整首页导航与统计文案，将「今日情报」「医疗相关文章」等遗留表达改为更符合 AI+X 定位的「今日推荐」「AI+X 候选文章」。
- 强化新用户引导：未登录用户点击添加研究方向时进入注册/登录流程；已登录但无方向时显示设置引导。
- 升级文章卡片信息结构：
  - 中文标题优先展示
  - 保留原标题
  - 展示来源、日期、质量分
  - 展示个人匹配度
  - 展示推荐理由
  - 展示跨领域迁移价值
  - 展示阅读优先级
  - 保留收藏、有用、不相关、已读反馈按钮
- 接入 `/api/article/reading-brief` 到前端主流程：点击「阅读 brief」即可展开结构化中文阅读卡片。
- 研究方向管理页展示结构化画像摘要，并展开显示：
  - expanded keywords
  - core methods
  - adjacent methods
  - application domains
- 修复 `/api/subscribe/me` 在用户未开启邮件订阅时不返回研究方向列表的问题，让「只填画像、不订阅邮件」的新用户路径也成立。
- 安全上继续保持服务端 API key 不下发；顺手对文章摘要、公众号分析标题等前端注入点做了 HTML 转义。

## 为什么这么做

外部用户第一次打开页面时，最需要理解的不是「这里有很多内容」，而是「这个产品如何帮我的研究省时间」。因此本阶段把页面重心从内容工具和创作辅助，前移到研究雷达的核心体验：

1. 先理解产品承诺。
2. 注册或登录。
3. 填写研究方向。
4. 看到与自己方向相关的推荐。
5. 用阅读 brief 快速判断是否值得精读。
6. 用反馈按钮留下偏好信号。

这条路径更适合 MVP 演示，也更贴近 AI+X 交叉研究者的真实工作流。

## 优点

- 不重写项目，只在现有 `server.py` 单体结构内补齐体验，改造成本低。
- 后端已有的结构化画像、推荐解释、反馈和 reading brief 能力被前端串起来，产品闭环更完整。
- 中文标题、推荐理由、迁移价值、阅读优先级让用户不用点进原文，也能快速判断阅读价值。
- 未开启邮件订阅也能管理研究方向，降低新用户试用门槛。

## 不足

- 前端仍是内嵌在 `server.py` 的大字符串，继续扩展会越来越难维护。
- 推荐理由和迁移价值有缓存 brief 时更准确；没有 brief 时仍使用启发式兜底。
- 个人匹配度依赖后台画像打分，刚添加方向后的部分文章可能短时间显示「待画像匹配」。
- 仍保留创作工具、动画解析等旧功能入口，MVP 展示时需要讲清主线，避免用户被次要能力分散注意力。

## 简历/项目介绍表达

> 负责将原医疗 AI 情报工具升级为 AI+X 交叉研究雷达 MVP：重构首页信息架构与文章卡片体验，串联结构化研究画像、个性化匹配分、推荐解释、跨领域迁移价值、用户反馈和中文 reading brief，使用户可以在注册后输入研究方向，并快速获得每日 5-10 篇高价值论文推荐与结构化阅读建议。

## 后续建议

1. 将 `server.py` 拆分为 `routes/ services/ templates/ static/`，降低前端迭代成本。
2. 将 `reading_brief.transfer_value`、用户反馈和历史点击纳入 rerank，而不只是展示。
3. 为新用户添加 2-3 个示例研究方向模板，降低画像填写门槛。
4. 增加「重新计算我的推荐」按钮，让新画像能更快触发个性化评分。
5. 为公开演示准备一份带样例用户和样例文章的 seed 数据库。
