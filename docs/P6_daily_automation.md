# P6 每日自动化与运行日志复盘

## 做了什么

- 新增 `pipeline_runs` 表，用于记录 pipeline 每次运行的类型、状态、开始时间、结束时间、摘要信息和日志。
- 新增 `run_daily_pipeline_job()`，通过子进程运行完整 `main.py --db ... daily`，覆盖抓取、评分、个性化评分、标题、推送和趋势生成。
- 新增 `schedule_daily_pipeline()`，使用 Python 标准库 `threading.Timer` 实现每日定时任务。
- `.env.example` 增加：
  - `ENABLE_DAILY_SCHEDULER=false`
  - `DAILY_RUN_AT=08:00`
- 服务启动时只有在 `ENABLE_DAILY_SCHEDULER=true` 时才开启自动 daily，避免本地开发误发邮件。
- 新增管理员接口：
  - `GET /api/pipeline-runs` 查询最近运行记录
  - `POST /api/run-daily` 手动触发完整 daily pipeline

## 为什么这么做

原系统有 `main.py daily`，但部署 Web 服务后不会自动每日执行完整流程。这会导致用户以为已经订阅，但实际上没人触发抓取和推送。P6 把每日任务变成服务能力，并补上运行日志，便于上线后排查失败。

## 优点

- 默认不开启，避免开发环境误触发真实发信。
- 不新增 APScheduler/Celery 等依赖，部署复杂度低。
- 运行记录入库，方便展示后台健康状态。
- 手动任务和自动任务共用同一套 daily 入口，行为一致。

## 代价和不足

- `threading.Timer` 适合单实例部署；如果未来多实例部署，需要外部 cron、队列或分布式锁。
- 子进程最长超时为 1 小时，大规模用户增长后可能需要拆成队列任务。
- 目前仅记录运行日志，没有邮件/Slack 告警。

## 简历/项目介绍表达

> 为研究情报系统补充每日自动化调度和可观测运行日志：通过环境变量控制定时任务，自动执行抓取、评分、个性化推荐和邮件推送，并将运行状态、失败原因和日志落库，支持管理员查询和手动触发。

## 复盘

这一阶段解决的是“可靠交付”问题。推荐系统不只是算法准，还要每天稳定跑、失败可见、可手动补救。对真实用户来说，可靠性本身就是产品体验的一部分。
