# P9 精准研究雷达与信号降噪复盘

## 做了什么

- 将首页默认文章流从“按类别全部展开”调整为“今日精选推荐 + 更多候选折叠”，随后继续收敛为“今日必读”：
  - 默认只展示 3-5 篇左右高价值候选。
  - 低匹配、略读、候选文章进入“更多候选”。
  - 用户标记“不相关 / 已读 / 跳过 / 隐藏”的文章不再进入精选和更多候选。
- 新增 `attach_radar_recommendations()`，在 `/api/digest` 返回前为 digest 附加：
  - `_radar_picks`
  - `_more_candidates`
  - `_recommendation_mode`
  - `_recommendation_notice`
  - `_has_relevance_scores`
  - `_radar_pick_count`
- 明确推荐模式：
  - `personalized`：已有研究画像且当前文章已有个性化匹配分。
  - `profile_pending`：用户已填写画像，但当前文章还没有完成个性化评分。
  - `generic`：未登录或未填写画像，只能使用质量分兜底。
- 首页文章卡片保留并强化研究者决策字段：
  - 中文标题
  - 原标题
  - 来源、日期、质量分
  - 个人匹配度
  - 推荐理由
  - 跨领域迁移价值
  - 阅读优先级
  - 收藏 / 有用 / 不相关 / 已读反馈
- 将“新概念预警”改为“近期冒头信号”，避免把站内语料统计误包装成全网新概念发现。
- 为近期冒头信号增加：
  - `confidence`
  - `evidence_count`
  - `openalex_oldest_year`
  - `scope_note`
- 将“研究热点追踪”改为“本站语料热点追踪”，明确它是近 7 天本站抓取语料相对前 23 天基线的统计信号。
- 为热点追踪增加：
  - `baseline_count`
  - `baseline_rate`
  - `growth_pct`
  - `avg_quality`
  - `confidence`
  - `scope_note`
- 收紧热点候选逻辑，过滤过宽、过泛、低质量或代表文章不足的关键词。
- 缓存读取增加字段完整性判断，避免旧缓存继续展示缺少置信度和证据字段的数据。

## 为什么这么做

用户反馈的核心问题不是页面没有内容，而是内容过多且不够“替我判断”。尤其“顶刊论文”一旦全部展开，读者会被大量略读内容淹没，产品从研究雷达退化为普通信息流。

这轮调整的原则是：默认界面只承担“今天我应该优先看什么”的任务，更多内容作为备用候选折叠。研究者可以展开查看更多，但产品不应该把所有抓到的论文都推到用户眼前。

“新概念预警”和“研究热点追踪”也需要降级表达。当前系统的底层逻辑主要来自站内抓取语料的时间窗口、词频变化、质量分和 OpenAlex 年份校验；它不是一个完整的全网知识发现系统，也不是 DeepSeek 缺失导致不准。DeepSeek 主要负责生成中文解释，真正的候选发现仍然是统计规则和外部年龄校验。

## 优点

- 首页注意力更集中，用户打开后更接近“看 3-5 篇今日必读”，而不是被顶刊长列表压住。
- 推荐状态更诚实：系统会告诉用户当前是个性化、画像待评分还是通用兜底。
- 负反馈开始真正影响首页展示，用户点“不相关/已读”后能立即降低噪音。
- 新概念和热点模块的可信边界更清楚，不再暗示“全网新概念”或“绝对热点”。
- 统计信号带证据字段，后续可以继续演化为可解释的 research signal dashboard。

## 代价和不足

- 当前精选规则仍是启发式排序，不是训练出来的推荐模型。
- `profile_pending` 状态下仍依赖质量分兜底，个性化体验需要等待 daily pipeline 或手动更新生成相关性评分。
- “近期冒头信号”仍依赖关键词抽取和 n-gram 统计，对同义词、缩写、概念层级的归并还比较粗。
- OpenAlex 年份校验按标题搜索，只能作为辅助证据，不能证明概念首次出现时间。
- 热点追踪只反映本站抓取源和抓取窗口，不代表整个学术社区的真实热度。

## 简历/项目介绍表达

> 针对论文推荐首页信息过载问题，设计并实现“今日必读 + 候选折叠”的研究雷达机制：结合个性化相关性分、论文质量分、阅读优先级和用户负反馈，将默认信息流收敛为每日 3-5 篇高价值推荐；同时为新概念和热点追踪增加置信度、基线、增长率和证据字段，避免将站内统计信号误表达为全网结论，提升产品可信度和可解释性。

## 后续建议

- 将 `useful / irrelevant / read / star` 转为可学习的用户偏好权重。
- 为研究画像新增“负向关键词”和“不感兴趣领域”，进一步压低不相关顶刊论文。
- 在 daily pipeline 结束后强制刷新相关性评分，减少 `profile_pending` 出现时间。
- 将新概念候选接入 embedding 聚类，合并同义表达和近义术语。
- 为热点追踪增加 source coverage 说明，例如 arXiv、RSS、GitHub、商业源分别贡献多少。

## P9.1 继续降噪

用户再次反馈首页文献仍然太多后，继续将默认推荐从“精选推荐”收敛为“今日必读”：

- 首页默认最多展示 5 篇。
- 每个类别最多进入 2 篇，避免“顶刊论文”继续垄断首页。
- 个性化精选阈值提高到：
  - 个人匹配度 ≥ 8；
  - 或个人匹配度 ≥ 7 且质量分 ≥ 8；
  - 或个人匹配度 ≥ 6.5 且阅读建议为精读。
- 无个性化评分时，通用兜底阈值从质量分 8.0 提高到 8.7。
- 补充候选从 30 篇减少到 12 篇，并默认折叠。

这次调整的判断是：MVP 首页宁可少推，也不要多推。对研究者来说，“没有足够把握就不打扰”比“把所有可能相关都列出来”更接近真实价值。
