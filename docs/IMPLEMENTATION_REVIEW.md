# AI+X 交叉研究雷达完整改造复盘

## 本次改造目标

把原来的垂直「医疗 AI 每日情报」原型，升级为可面向多领域交叉研究者展示的「AI+X 交叉研究雷达」：

- 更安全：不暴露密钥，不硬编码个人 Cookie/SMTP 授权码。
- 更通用：从单一医疗 AI 扩展到 AI+X 多领域研究方向。
- 更个性化：用户研究方向从关键词升级为结构化画像。
- 更高效阅读：给出结构化阅读 brief，而不是只推标题和摘要。
- 更可运营：有每日调度、推送日志、运行日志。
- 更可验证：有 benchmark 脚手架和可量化指标。

## 完成的阶段

1. `P0_security_baseline.md`：安全清理与环境配置。
2. `P1_P2_positioning_and_profiles.md`：产品定位泛化与结构化研究画像。
3. `P3_P5_recommendation_reading_feedback.md`：推荐解释、反馈闭环和高效阅读卡片。
4. `P6_daily_automation.md`：每日自动化和运行日志。
5. `P7_benchmark_framework.md`：benchmark 脚手架和评估方法。

## 核心能力变化

### 改造前

- 医疗 AI 垂直情报站。
- RSS 抓取 + AI 评分 + 邮件推送。
- 关键词和研究方向混用，个性化能力较弱。
- 收藏是全局字段，多用户会互相影响。
- 没有完整每日 Web 服务调度。
- 没有推荐质量评估框架。

### 改造后

- AI+X 跨领域研究雷达。
- 支持多领域配置和结构化研究画像。
- 新增用户反馈闭环：收藏、有用、不相关、已读。
- 新增结构化阅读 brief：研究问题、方法、结果、数据集、代码、迁移价值、局限、阅读优先级。
- 新增推送日志和 pipeline 运行日志。
- 新增可选每日调度。
- 新增 benchmark 数据表、样例 query 和评估脚本。

## 偏差与风险检查

- 已清理硬编码 key/cookie/SMTP 授权码，并修复服务端 key 下发接口。
- 已保留旧字段兼容，避免破坏历史数据库。
- 已用临时数据库验证迁移能初始化。
- 已运行 `compileall`，代码能通过 Python 编译检查。
- 已运行 benchmark 脚本，空库下能正常输出 `N/A` 指标。
- 当前仍保留 `medai.sugarclaw.top` 作为现有部署域名；这是品牌迁移问题，不影响功能安全。
- 当前仍是单体 `server.py`，功能变强但维护压力仍在，后续应拆分模块。

## 优势

- 有清晰差异化：不是大而全搜索，而是研究方向驱动的每日少量高价值推荐。
- 有中文高效阅读能力：适合国内研究生、工程师、AI 产品/行业研究人群。
- 有反馈闭环和 benchmark，便于证明推荐质量，而不是只讲“AI 精准推荐”。
- 可从医疗 AI 自然扩展到 AI+生物、AI+材料、机器人、HCI、教育、金融等方向。

## 不足

- 当前推荐排序仍以关键词和 LLM 打分为主，尚未真正接入 embedding/向量召回。
- 用户反馈已记录，但尚未完全进入排序公式。
- `reading-brief` 依赖 LLM，缺 key 时体验会退化。
- 定时调度适合单实例，未来多实例部署需要外部任务系统。
- benchmark 目前是脚手架，需要真实文章和人工标注才能产出可信指标。

## 简历项目介绍版本

> AI+X 交叉研究雷达：面向跨领域研究者的个性化论文推荐与高效阅读系统。用户只需描述研究方向，系统自动从 RSS、arXiv、GitHub 和行业资讯中筛选相关论文/项目，生成中文推荐理由和结构化阅读 brief，并通过每日邮件推送。项目实现了结构化研究画像、用户反馈闭环、每日自动化调度、推送日志和自建 benchmark 评估框架，支持用 Precision@5、nDCG@10 等指标持续验证推荐质量。
