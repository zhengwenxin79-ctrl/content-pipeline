# P3-P5 推荐解释、反馈闭环与高效阅读复盘

## 做了什么

- 新增 `user_article_feedback` 表，记录用户对文章的行为反馈：
  - `star`
  - `useful`
  - `irrelevant`
  - `read`
  - `skip`
  - `hide`
- 新增 `delivery_logs` 表，记录每日/手动推送给用户的文章集合、状态和失败原因。
- 将收藏逻辑从全局 `articles.is_starred` 升级为用户级收藏，避免多人使用时互相污染。
- `/api/digest` 返回每篇文章的用户反馈状态和 `is_starred`。
- 新增 `/api/article/feedback`，前端可提交“有用 / 不相关 / 已读”等反馈。
- 首页文章卡片新增轻量反馈按钮，用户无需进入复杂设置即可留下推荐信号。
- 新增 `/api/article/reading-brief`，按结构化 JSON 输出：
  - 一句话结论
  - 研究问题
  - 方法/系统思路
  - 关键结果
  - 数据集
  - 代码/模型/工具
  - 与用户研究方向关系
  - 跨领域迁移价值
  - 局限性
  - 阅读优先级
  - 估计阅读时间
  - 标签
- 升级原有“深度分析” prompt，使页面现有分析也更贴近高效阅读卡片。

## 为什么这么做

这个产品的竞争点不应该是“数据库比别人全”，而应该是“每天帮用户更快判断什么值得读”。因此必须同时补三件事：

- 推荐解释：告诉用户为什么这篇和他有关。
- 用户反馈：让系统知道哪些推荐真的有用。
- 高效阅读：把论文压缩成可判断、可迁移、可行动的结构化卡片。

## 优点

- 从一次性推荐走向可学习的推荐闭环。
- 多用户收藏隔离，为公开试用打基础。
- `reading-brief` 输出结构稳定，后续可用于前端卡片、邮件摘要、benchmark 标注和简历展示。
- 推送日志可支持后续统计打开率、失败率、用户覆盖和推荐质量。

## 代价和不足

- 目前反馈信号已经采集，但还没有完全进入排序公式；下一步应把 `useful/irrelevant/read/star` 转成个性化权重。
- `reading-brief` 依赖 LLM；没有 API key 时只能使用普通摘要。
- 前端反馈按钮是轻量版本，还没有做“不再推荐类似内容”的细粒度偏好控制。
- 旧的 `articles.is_starred` 为兼容保留，长期看应迁移历史数据后弃用。

## 简历/项目介绍表达

> 设计并实现论文推荐反馈闭环和结构化阅读卡片：将全局收藏改造为用户级行为反馈，新增推送日志和阅读 brief API，使系统能记录“有用/不相关/已读”等推荐信号，并把论文拆解为研究问题、方法、结果、数据集、代码、迁移价值和阅读优先级，显著提升用户判断是否精读的效率。

## 复盘

这一阶段是产品从“信息聚合器”走向“研究助理”的分水岭。聚合器只负责把内容搬过来，研究助理要解释、排序、帮用户节省判断时间，并从用户反馈里变得更准。
